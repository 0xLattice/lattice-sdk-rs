# Rust SDK port

Source: `0xLattice/lattice-sdk` at
`3a1be07318f12b85f147e0a5ea55ae68a224e780`. Original MIT license retained.
This is a separate local repository on `codex/rust-platform-sdk`; unpublished.

## Implemented

- Shared Rust protocol primitives rather than a second consensus serialization.
- Canonical arbitrary-precision decimal JSON strings and JavaScript-safe integer
  presentation fields; missing optional fields accepted, explicit null rejected.
- Node URL policy (HTTPS, or loopback HTTP), operator cookie authorization,
  route component encoding, retained base-path prefix and chain-path queries.
- Native and browser async read client for health, chain information, root genesis, accounts,
  blocks, latest block, mempool, paged canonical blocks, child directories,
  block children, transactions/content IDs, chain spec and fee estimates. Redirects are not followed. Requests and body
  reads share a deadline and cancellation; declared and streamed response sizes
  are bounded before JSON parsing. Rustls verifies HTTPS server certificates.
- Seven read-client tests include actual loopback HTTP reads, encoded routes, authorization,
  large decimal values, malformed wire types, redirects, oversized declared and
  streamed bodies, stalled-body deadline and cancellation before dial. Pagination
  rejects repeated/out-of-order heights, invalid continuation, wrong chain paths
  and non-advancing child cursors; legacy unpaged child responses are filtered.
- Exact fee weighting and outbid calculation match 192 weight cases and 48 rates
  generated by the actual pinned TypeScript implementation. The reproducible
  generator builds that checkout and records revision and source/output hashes.
  Integer intermediate arithmetic avoids floating-point loss.

JSON answers remain unverified node claims. A read result does not prove a
canonical block, balance or content hash. Submission uses a separate explicitly configured transport.

- Endpoint resolution follows operator declarations down the requested path,
  checks that each host serves that exact path on the root network, preserves
  declaration order and submit-capability labels, and bounds sources, candidates
  and total requests. Results explicitly remain operator-declared claims.
  HTTPS/literal-public-address policy handles IPv4-mapped IPv6, NAT64 and 6to4.
  It matches 310 actual TypeScript URL cases. Resolver tests cover nested paths,
  wrong-network hosts, deduplication, private addresses, budget exhaustion, root
  404 versus failure, and injected transports ignoring cancellation/deadlines.
  Optional DNS lookup now rejects empty answers and any private/special address
  among otherwise public answers. The native reader can use Tokio DNS; injected
  lookups are bounded by the same deadline/cancellation policy. Like the
  reference hook, this preflight does not pin the connector's later DNS lookup
  and does not eliminate rebinding. Six endpoint tests cover these checks.

- Authenticated volume retrieval now includes private immutable verified results,
  complete-volume archive encoding/decoding, memory and HTTP transports, exact
  identity/SHA-256 CID validation, and UInt64 sparse proofs. The dedicated SDK
  CBOR decoder rejects floats/tags and noncanonical integers/maps. Its configurable
  default depth limit is 512 (64 Mi values); the TypeScript source has no explicit
  depth cap, so this is a resource-policy difference, not claimed unbounded parity.
  180 actual TypeScript differential cases cover CID/archive/CBOR/proof behavior.
  Real HTTP tests cover 64 MiB streamed overflow, declared size limits, media type,
  authorization, chain paths, 404, redirect refusal, deadlines and cancellation.

- Transaction composition now includes Ed25519 signing accounts, transfers,
  canonical body/envelope encoding, signature alias normalization and duplicate
  rejection, exact pre-signing size estimates, wire submission payloads and state
  growth ceilings. Accounts do not implement Debug/Serialize for secret material.
  27 actual TypeScript cases match public keys, addresses, body/envelope bytes,
  CIDs, deterministic signatures, payloads, sizes and growth (large integers and
  Unicode paths included). Encoding rejects cross-chain nonces above UInt64,
  matching the canonical encoder's current limit. Construction/signing is not
  validation or submission.

- Separate HTTP transaction submitter sends only to an explicitly configured
  endpoint (HTTPS or loopback HTTP), preserves query routing, never follows
  redirects, and bounds response bodies, deadlines and cancellation. Node refusal
  status/text is retained with known policy-reason classification. Optional pool
  counts must be nonnegative safe integers. `submit_signed` derives the expected
  transaction CID locally and rejects mismatching relay receipts. This confirms
  neither inclusion nor validity. Three real loopback tests cover payload bytes,
  authentication, receipt binding, refusals, counts, redirects and resource limits.
  No live-network submission was performed by these tests.

- Lazy breadth-first endpoint walking follows all pages, preserves failover
  cursors and halves oversized directory requests, resetting the page limit after
  success. Nine actual TypeScript scenarios match, including root errors, long
  names, cancellation and stopping early. HTTP tests verify response caps and
  that declared endpoints never receive root credentials.

- Sponsor proposal checks reconstruct exactly the requested transaction plus
  fee/pay actions, bind the sponsor key to its address and reject changed fields
  or extra signatures. Eighteen actual TypeScript cases match. The signature is
  retained for ordinary cryptographic validation; this is not an admission proof.
  Share hashing matches 77 TypeScript cases, including arbitrary signed nonces
  modulo 2^64 and strict lowercase prefix hex. Lazy CPU search matches six actual
  TypeScript ranges and tests cancellation/expiry. Its deadline is monotonic and
  must be based on request start time. Targets above UInt256 are rejected (the
  TypeScript low-level grinder truncates them, although its work parser rejects
  them).

- Sponsor HTTP client implements work requests, share submission, co-signature
  requests, storage uploads and storage status. Four real loopback tests include
  27 actual TypeScript parsing cases, exact request paths/bodies, work expiry
  measured from request start, streamed/declared response caps, UTF-8 BOM handling,
  refusal status, no redirects and in-flight cancellation. No live sponsor was
  contacted. Expiry uses a monotonic clock and rejects values outside its range;
  the TypeScript client can represent huge durations as Infinity, so this is an
  explicit conservative policy difference. Sponsor answers remain claims about
  credit/storage, and co-signatures still require normal admission validation.

- Canonical block/state/signed-envelope decoding and standalone Nexus PoW/work
  arithmetic match 50 actual TypeScript content cases and 11 target cases.
  UTF-16 signature ordering, optional-versus-null fields, integer limits,
  canonical hash preimages and continuity are covered. Decoders inherit the
  documented SDK CBOR resource limits; decoding alone does not verify a CID.
- LatticeClient composes node reads and verified volumes for latest/block,
  post-state, transaction collections and individual transactions. Three local
  HTTP integration tests exercise all ten projected block-field comparisons,
  corrupt content, root-only non-genesis PoW, committed body availability and
  requested transaction CID binding. Matching content does not establish chain
  membership, signatures, child securing proof, executed state or finality.

- ChainNodes implements cached discovery and round-robin reads, with shared
  in-flight requests, completion-based cache expiry and preserved transport
  errors. Thirteen TypeScript scenarios and local HTTP/concurrency tests cover
  discovery, retry and cancellation ownership.
- The `proofs` module integrates the separate `lattice-light-client-rs` Swift
  protocol port. `account_at_state` requires the caller's expected state root
  and address; `claim_at_block` requires the expected block CID, dictionary and
  key. A missing claim never becomes an absent value. Returned values have
  private construction and expose authenticated balance/stored nonce or optional
  claim value. Tests cover substitution, tampering, missing witnesses and
  duplicate claims. These helpers are a Rust integration addition, not a claim
  of TypeScript API parity. Caller-selected commitments still need independent
  chain/canonicality validation; account proofs do not bind a header hash to
  block bytes, and dictionary batches do not prove range completeness.

## Remaining

Expanded content interoperability and high-level submission workflows; end-to-end Rust/Swift node compatibility; cross-browser and worker validation; extending TypeScript differential coverage; cross-repository CI and
release manifests. The initial read-client tests do not establish SDK completeness.

## Browser runtime and transport

`wasm32-unknown-unknown` builds use Fetch, AbortController, streaming response
readers, browser timers, monotonic clocks and local spawned discovery futures.
Native builds retain Tokio, Rustls and Send futures. All HTTP clients share this
transport seam. Browser requests reject redirects and omit ambient credentials;
explicit authorization remains supported. Dropping a pending request or response
aborts its Fetch operation. Streaming budgets are checked before copying chunks
into WASM; the browser controls its own networking buffers.

Browser CORS, forbidden-header, mixed-content and TLS policies remain enforced.
Optional DNS preflight is unavailable and returns a configuration error when
requested. Browser timer throttling can delay deadlines in background tabs, and
CPU work must yield to process cancellation. No native socket/TLS customization
is exposed in browser builds. The API is a Rust crate usable from WASM; the smoke
example demonstrates wasm-bindgen embedding, not a drop-in JavaScript SDK export.

The actual Chrome run in `browser/evidence.json` verifies reads, authorization,
stream caps, timeout and cancellation aborts before headers and during bodies,
redirect rejection, volume authentication, submission, shared discovery and
entropy/sponsor search. `browser/README.md` reproduces it. Other browser engines,
workers and cross-origin deployment configurations remain unverified.

Actual Rust and unchanged pinned Swift daemon workflows now exercise signed
transfer inclusion, CID content reads, account and deposit-absence witnesses,
and durable restart (see `docs/node-integration.md` and evidence). This exposed
and fixed transaction-dictionary lookup: it resolves from the enclosing block
volume, rather than requesting an ordinary Header as a standalone volume.
